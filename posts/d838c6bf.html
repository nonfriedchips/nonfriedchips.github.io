JML 的自动化评测

JML 如此反人类面向机器的设计怎么能没有自动化评测方法呢，显然 JML 并不只是给 AI 看的语言（，接下来我们将介绍一些 JML 的自动评测方法

动态测试

  1. 使用 OpenJML 编译器将带有 JML 注释的源码编译为带有运行时检查 (RAC) 的 .class 文件

  2. 自动化生成测试数据（利用随机数据、边界值数据，或利用 JMLUnitNG/Randoop 自动生成）

  3. 运行测试用例。如果程序崩溃或抛出 JML 异常，则说明代码实现（或 JML 编写）存在问题

静态测试

将 JML 规格和 Java 代码翻译成逻辑表达式（中间语言如 Boogie/Why3），然后用 SMT 求解器（如 Z3-Solver）证明代码是否符合规格

  • OpenJML (ESC/Stack Check) + Z3-Solver

测试流程

  1. 下载 OpenJML 和对应的 Solvers

  2. 自动化静态检查

  3. 编译运行时断言

    静态检查有时因为算力或 JML 语法过于复杂而产生 Unknown 或超时。因此，最稳妥的自动化评测还是依赖动态测试。

  4. 生成数据并测试

    • 使用 JMLUnitNG 生成 TestNG

    • 编写一个测试桩（Test Runner），结合参数化测试（Parameterized Tests），构造边界值。

      • 正常输入：验证后置条件（ensures）和不变性（invariant）。
      • 异常输入：故意输入违反前置条件（requires）的数据。如果代码抛出了 JMLRequiresError，说明前置拦截正确；如果没有抛出而往下执行了，说明代码健壮性有漏洞。

    • 随机生成大规模的指令/数据流。

      将数据喂给待测代码（编译了 RAC） 和 标程（或者是其他人的代码）。

      检查待测代码是否抛出了 JMLAssertionError，并对比最终的输出结果。

字符串匹配算法

在 hw10 中出现了令人啼笑皆非的场景

由于文本串和模式串都极短，很难区分 KMP 和 Brute Force 两种算法，因此聪明的你想到了猛猛加数据压测来区分这两种算法

在对代码进行高强度压力测试中，由于服务器已经变成了

于是服务器决定随机通过所有采取 KMP 和 Brute Force 的代码 ( 作者就是不幸被随机判定为不通过的那位 )

我们来分析一下这个有趣的现象，并从这个现象来理解不同的字符串匹配算法以及他们的优劣之处

为何两者的用时差不多

在算法竞赛中，我们通常使用时间复杂度来区分算法性能的优劣，这是因为在算法竞赛的数据规模下，不同时间复杂度算法的用时会有很显然的区分。（而且选手写了访存不友好的算法日不过去就会痛骂出题人卡常）

不过聪明的小朋友早在大一冲榜数据结构这门课的大作业时就发现

《我引以为傲的哈希算法被写 Trie 树的名门正派说是轮椅，时间还碾了 Trie 树两条街》

这是因为裸的 Trie 树在当时的场景会对不连续的内存进行大量随机访问，而哈希算法访问内存几乎是连续的。

现在大家也已经完全了解了，访存性能对于一个程序影响会很大 (这就是为什么我不在这个字符串匹配中写 SAM 绝对不是我觉得不好写)

现在我们令目光回到暴力身上，来看为什么他这么快，实际上 String.contains() 这个函数相当高效

他在比较的时候使用了 SIMD 技术，CPU一次将复数字节的数据加载到向量寄存器中，一个 CPU 时钟周期内完成整块数据的对比（并且对于这些批量操作的数据，可以更加方便进行多发射。（待验证））（我们后续将介绍一个类似的算法）

故而在模式串极短的情况下，CPU只需一个指令就能完成批量的比较

而 KMP 访存不友好，需要预处理，预测不友好，成为了牢九门（

接下来我们将一次介绍多种字符串匹配算法

我们先补充基础知识

在字符串匹配中，需要寻找的字符串叫模式串，即该作业中的 spam 关键字，而待判断的串叫文本串

如：“在串’abc_wiki_abc’ 寻找 ‘wiki’，其中 ‘wiki’ 出现了 1 次”，上面这个匹配操作中，“abc_wiki_abc” 就是文本串，“wiki” 就是模式串

KMP

这个大家貌似已经学过了，其算法本质是，先前的匹配中蕴含了一些信息，故在错配时，我们不应该全部清空，而是充分利用前后缀相同的部分，于是我们预处理出失配指针，在模式串上建立自动机进行匹配

可以发现这个算法能够将模式串上的信息压缩到极限，不难猜出 KMP 算法适合进行长模式串的匹配

该算法复杂度为 O(N+M)，在渐进时间复杂度意义上达到字符串匹配理论复杂度极限。

BM (长文本串 长模式串 随机字符)

BM 算法 ( Boyer-Moore 算法 ) 是众多编辑器常用的匹配算法。

他的核心思想是：从右向左比较，大幅度向后跳跃

普通的暴力匹配时把模式串在文本串上一步一步往后挪。而 BM 算法在发现不匹配时，能根据已经掌握的信息，一次性向后滑动好几个字符，直接跳过那些绝对不可能匹配成功的区域。

它之所以能实现大步跳跃，全靠两个核心规则：坏字符规则和好后缀规则。

坏字符规则

当模式串和文本串从右向左逐个字符比较时，一旦发现某个字符不匹配，主串中这个不匹配的字符就叫做”坏字符“。

这个时候怎么跳？看图中的逻辑：

  1. 在文本串的第 11 位发现了坏字符 C，而此时模式串对应的位置是 A ( 不匹配 )
  2. 我们去模式串中，寻找最后一次出现 C 的位置 ( 图里是在第 7 位 )
  3. 我们把模式串向后滑动，让这两个 C 对齐，继续下一次比较
好字符规则

如果从右向左匹配的时候，已经连续对上了好几个字符，突然卡住了，那些已经对上的字符，就叫做”好后缀“

这个时候的滑动策略是：

  • 在模式串中，看前面还有没有别的地方也包含这个”好后缀“。如果有，就把前面的”好后缀“滑动到与文本串对齐。
  • 如果前面没有完全一样的”好后缀“，就找模式串的前缀能不能和好后缀的后半部分重合。
  • 如果仍然没有，就直接把整个模式串滑过这段好后缀

最终在两个规则中选择跨度最大的那一个。

时间复杂度 最好 O(n/m)O(n/m)O(n/m) 最坏 O(n×m)O(n\times m)O(n×m) 在大字符集中，能快速跳过，效率极高

BM算法的一些变体
  • Boyer-Moore-Horspool 砍掉好后缀规则，只保留坏字符规则。但计算滑动时，永远固定看当前匹配窗口的最后一个字符。大幅简化了代码和内存消耗。因为实际大字符集中好后缀触发概率低，Horspool 在工业界比原版 BM 更常用。
  • Turbo-BM 引入记忆化机制。记录上一轮已经匹配成功的子串，下一轮挪动后直接跳过该区域不作比对。彻底解决了原版 BM 的漏洞。将最坏时间复杂度死死锁在 O(n)O(n)O(n)，同时保持了最好情况的亚线性速度。
  • Real-Time BM 限制了每一步查找和跳转的最大时间边界，防止在遇到特定周期性字符时发生局部卡顿。专为实时操作系统、硬件防火墙设计，确保搜索的“确定性阻抗”。
  • BNDM Backward Non-deterministic Dawg Matching，型向非确定性有限状态自动机匹配
  • Sunday 匹配时可以从左往右，但跳转时，只看主串中“当前参与匹配的这一段”的【再后一个字符】
  • Sunday-KMP 在Sunday的基础上结合KMP

  • 进行位运算状态转移

匹配中的麻烦？

如果字符集过大或模式串过长，那么匹配速度将大打折扣。

在 Bitap 中，我们用一个二进制数来表示模式串的字符。

算法维护一个状态值，用它的二进制位来记录当前匹配到了模式串的第几个字符。

每读入主串的一个新字符，就通过右移和一次按位或来更新状态。

这种将状态压缩进二进制的做法，让它能直接享受现代 CPU 在硬件级别对位运算的超高性能优化。

实现：

假如我们要寻找模式串 "cat"

  1. 预处理（生成字符掩码表）：为字符集里的每个字符生成一个长度为 3 的二进制数。在它出现的位置放 0，其余地方放 1。

    • C 出现第 1 位 →\rightarrow→ 110

    • A 出现第 2 位 →\rightarrow→ 101

    • T 出现第 3 位 →\rightarrow→ 011

    • 其它没出现的字符 →\rightarrow→ 111

  2. 状态转移：初始状态 R = 111。每扫描主串一个字符，执行一次状态转移：

    新状态 R=((R≪1)∣当前字符的掩码)\text{新状态 } R = ((R \ll 1) \mid \text{当前字符的掩码}) 新状态 R=((R≪1)∣当前字符的掩码)

  3. 结束检查：只要 R 的最高位（第 3 位）变成了 0，就说明 “cat” 三个字母连续匹配成功了。

SAM ( 多文本串 单模式串 )

SAM极其困难，并且常数过大，此处不涉及其实现

后缀自动机（suffix automaton, SAM）是一个能解决许多字符串相关问题的有力的数据结构．

举个例子，以下的字符串问题都可以在线性时间内通过 SAM 解决：

  • 在另一个字符串中搜索一个字符串的所有出现位置；
  • 计算给定的字符串中有多少个不同的子串．

直观上，字符串的 SAM 可以理解为给定字符串的 所有子串 的压缩形式．值得注意的事实是，SAM 将所有的这些信息以高度压缩的形式储存．对于一个长度为 nnn 的字符串，它的空间复杂度仅为 O(n)O(n)O(n) ．而且，构造 SAM 的时间复杂度也仅为 O(n)O(n)O(n) ．准确地说，一个 SAM 最多有 2n−12n-12n−1 个结点和 3n−43n-43n−4 条转移边．
